# Seven + OpenClaw na mesma VPS

O painel chama `/v1/seven/chat` no backend local (porta 8737). Para modelos remotos, essa rota transmite a mensagem para o Gateway OpenClaw em `127.0.0.1:18789`, usando o mesmo ID de conversa para manter a sessão. O token fica apenas no servidor. Para modelos Ollama locais, a rota usa `127.0.0.1:11434/api/chat` diretamente para evitar o prompt completo do agente na CPU da VPS; o modelo selecionável ainda vem do catálogo `openclaw models list --json`, e as instruções de conversa são lidas do workspace local do OpenClaw. O painel continua responsável por voz e edição visual das notas.

No chat rápido, modelos `ollama/*` usam até oito turnos recentes enviados pelo painel e o arquivo [openclaw-local-chat/AGENTS.md](openclaw-local-chat/AGENTS.md). Não há ferramentas nem busca de memória nessa rota. O Qwen 3.5 0,8B é a escolha inicial no painel; modelos remotos usam explicitamente o agente `openclaw/main`, pois a instalação tem vários agentes e a rota genérica sem proprietário retorna HTTP 400. A escolha explícita de "Padrão do OpenClaw (remoto)" continua disponível. A conta de modelos e as chaves de API remotas ficam no OpenClaw. O Ollama recebe `OLLAMA_MAX_LOADED_MODELS=1` via systemd para impedir que vários modelos locais esgotem os 8 GB de RAM da VPS. Sessões de agentes distintos não compartilham histórico interno; o painel continua mostrando o histórico local da conversa.

1. Instale o OpenClaw para o usuário `sevenjarvis`, com `HOME=/var/lib/seven-openjarvis`, usando a instalação local sem elevar privilégios (`install-cli.sh --runtime-only`). O serviço Seven aponta `OPENCLAW_BIN` para `/var/lib/seven-openjarvis/.openclaw/bin/openclaw`.
2. Use [openclaw.json5.example](openclaw.json5.example) como referência para `/var/lib/seven-openjarvis/.openclaw/openclaw.json`. Ajuste o modelo principal e os fallbacks ali. A configuração `agentRuntime: openclaw` executa o agente no OpenClaw. Para listar os modelos locais instalados no Ollama, adicione `OLLAMA_API_KEY=ollama-local` ao ambiente do Gateway e mantenha `ollama/*` no escopo de modelos; o OpenClaw descobre os modelos em `127.0.0.1:11434`. O painel agrupa pelo campo `local` do catálogo do OpenClaw. O Gateway deve ficar em loopback; o Caddy não deve publicar a porta 18789. Instale os arquivos de [openclaw-workspace](openclaw-workspace) no workspace indicado pela configuração e remova o `BOOTSTRAP.md` gerado inicialmente, pois o Seven já tem identidade definida. O usuário `sevenjarvis` precisa ler e escrever no cofre, que também é `SEVEN_BRAIN_VAULT` no serviço Seven.
3. O Gateway roda pela unidade [seven-openclaw.service](seven-openclaw.service) e usa `/etc/seven-openclaw.env` com `OPENCLAW_GATEWAY_TOKEN` e a chave do provedor, acessível somente ao administrador. O backend Seven lê apenas o token bruto em `/var/lib/seven-openjarvis/.openclaw/gateway.token`, acessível ao usuário `sevenjarvis`. Use o mesmo token nos dois arquivos. Reinicie o Gateway e `seven-openjarvis.service` após instalar a configuração. O serviço Seven usa `--agent none`; sua rota de chat só chama Ollama diretamente para o modo local rápido, sem ativar o antigo extrator de memória.
4. Confira `openclaw models list --json`, `openclaw memory status` e `openclaw memory index --force --agent main` no mesmo usuário do Gateway. Acesse `/v1/seven/models` pelo domínio protegido do painel e converse com o Seven. Depois de enviar uma mensagem, confirme sua entrada no inbox; após a revisão diária, confira a nota em `/brain/notes` e no cofre.

Na página `/seven/settings`, o backend Seven usa `openclaw models auth paste-api-key`, `models auth logout` e `config set` como ponte administrativa local. As chaves ficam no auth store do OpenClaw; o navegador recebe somente o estado de conexão. A rota administrativa exige o usuário autenticado enviado pelo Caddy (`X-Seven-Auth-User`) e a origem HTTPS do painel em requisições de escrita. O serviço Seven define `SEVEN_ADMIN_USER` e `SEVEN_ADMIN_ORIGIN`. Não publique a porta 18789. Se uma chave antiga ainda estiver em `/etc/seven-openclaw.env`, migre-a para o auth store e remova essa variável antes de permitir troca/remover pelo painel, para que a chave antiga não continue ativa como fallback.

Se o agente do OpenClaw usar sandbox, monte o cofre como diretório de leitura e escrita nesse sandbox; `memory.search.extraPaths` sozinho concede indexação, não acesso de escrita às ferramentas. Configure o modelo principal e os fallbacks somente no OpenClaw.

O processo OpenJarvis ainda mantém o mecanismo Ollama para telas antigas do painel que dependem das rotas genéricas `/v1/*`. Ele não processa mensagens enviadas pela página Seven. A remoção desse mecanismo exige migrar ou aposentar as telas antigas, separadamente, para não quebrá-las.

## Memória automática do Seven

Cada mensagem enviada pela rota `/v1/seven/chat` é acrescentada antes da inferência a `~/.openclaw/seven-memory-inbox/YYYY-MM-DD.jsonl`, com `fsync`. Assim, uma resposta interrompida continua disponível para revisão. Se o registro falhar, a rota devolve erro em vez de perder a mensagem silenciosamente.

O job OpenClaw `seven-memory-nightly` roda às 04:10 em `America/Araguaina`, sem entrega de mensagem. Ele executa [seven_memory_review.py](seven_memory_review.py) como `sevenjarvis`. O revisor usa o agente OpenClaw `memory-reviewer` com `openai/gpt-6-luna`, em lotes, para decidir quais fatos merecem nota. Um processo separado consulta o Ollama local `qwen3.5:2b` para escolher a nota; o script grava o Markdown e confirma o marcador de idempotência. O modelo escolhido no chat do Seven não participa desse fluxo. O job guarda IDs processados em `~/.openclaw/seven-memory-review.sqlite` e tenta novamente após falhas. O cofre segue em `~/Documents/Seven Brain`.

Defina `skills.workshop.autonomous.mode` como `propose` no OpenClaw para impedir revisões semanais automáticas de skills, inclusive no perfil do revisor, que poderiam consumir tokens remotos fora do job de memória.

Para instalar, coloque o script no HOME do serviço, crie o agente `memory-reviewer` com workspace [openclaw-memory-reviewer](openclaw-memory-reviewer) e modelo `openai/gpt-6-luna`, e declare o job de comando com `--command-argv '["python3","/var/lib/seven-openjarvis/.openclaw/seven_memory_review.py"]' --cron '10 4 * * *' --tz America/Araguaina --no-deliver`. Não configure o job como agente de conversa nem exponha o Gateway ou o Ollama à internet. A gravação usa a conta do serviço com acesso de escrita ao cofre.
