# Seven + OpenClaw na mesma VPS

O painel chama `/v1/seven/chat` no backend local (porta 8737). **Toda conversa**, qualquer que seja o modelo escolhido, segue para o Gateway OpenClaw em `127.0.0.1:18789`, usando o mesmo ID de conversa. O backend não interpreta palavras-chave nem decide quando consultar squads ou salvar notas. O token fica apenas no servidor. O painel continua responsável por voz e edição visual das notas.

O padrão do chat é o agente `openclaw/main`, pois a instalação tem vários agentes e a rota genérica sem proprietário retorna HTTP 400. O painel oferece apenas os modelos remotos do catálogo; modelos Ollama podem continuar instalados para outras tarefas, mas não há desvio direto do chat para Ollama. A conta de modelos e as chaves de API ficam no OpenClaw.

1. Instale o OpenClaw para o usuário `sevenjarvis`, com `HOME=/var/lib/seven-openjarvis`, usando a instalação local sem elevar privilégios (`install-cli.sh --runtime-only`). O serviço Seven aponta `OPENCLAW_BIN` para `/var/lib/seven-openjarvis/.openclaw/bin/openclaw`.
2. Use [openclaw.json5.example](openclaw.json5.example) como referência para `/var/lib/seven-openjarvis/.openclaw/openclaw.json`. Ajuste o modelo principal e os fallbacks ali. A configuração `agentRuntime: openclaw` executa o agente no OpenClaw. Para listar os modelos locais instalados no Ollama, adicione `OLLAMA_API_KEY=ollama-local` ao ambiente do Gateway e mantenha `ollama/*` no escopo de modelos; o OpenClaw descobre os modelos em `127.0.0.1:11434`. O painel agrupa pelo campo `local` do catálogo do OpenClaw. O Gateway deve ficar em loopback; o Caddy não deve publicar a porta 18789. Instale os arquivos de [openclaw-workspace](openclaw-workspace) no workspace indicado pela configuração e remova o `BOOTSTRAP.md` gerado inicialmente, pois o Seven já tem identidade definida. O usuário `sevenjarvis` precisa ler e escrever no cofre, que também é `SEVEN_BRAIN_VAULT` no serviço Seven.
3. O Gateway roda pela unidade [seven-openclaw.service](seven-openclaw.service) e usa `/etc/seven-openclaw.env` com `OPENCLAW_GATEWAY_TOKEN` e a chave do provedor, acessível somente ao administrador. O backend Seven lê apenas o token bruto em `/var/lib/seven-openjarvis/.openclaw/gateway.token`, acessível ao usuário `sevenjarvis`. Use o mesmo token nos dois arquivos. O serviço Seven usa `--agent none`; sua rota de chat chama o OpenClaw.
4. Confira `openclaw models list --json`, `openclaw mcp doctor seven-operations --probe` e `openclaw memory status`. Acesse `/v1/seven/models` pelo domínio protegido e converse com o Seven. Teste uma consulta de squad e uma busca de nota sem escrita antes de delegar ou salvar.

Na página `/seven/settings`, o backend Seven usa `openclaw models auth paste-api-key`, `models auth logout` e `config set` como ponte administrativa local. As chaves ficam no auth store do OpenClaw; o navegador recebe somente o estado de conexão. A rota administrativa exige o usuário autenticado enviado pelo Caddy (`X-Seven-Auth-User`) e a origem HTTPS do painel em requisições de escrita. O serviço Seven define `SEVEN_ADMIN_USER` e `SEVEN_ADMIN_ORIGIN`. Não publique a porta 18789. Se uma chave antiga ainda estiver em `/etc/seven-openclaw.env`, migre-a para o auth store e remova essa variável antes de permitir troca/remover pelo painel, para que a chave antiga não continue ativa como fallback.

O servidor MCP [seven_mcp.py](seven_mcp.py) roda via stdio, como `sevenjarvis`, com Python 3.12 e `mcp==2.2.0` em venv isolado (`/var/lib/seven-openjarvis/.openclaw/mcp-venv`). Instale `python3.12-venv`, crie o venv, instale o pacote e copie o script. Cadastre `seven-operations` com `openclaw mcp add seven-operations --command /var/lib/seven-openjarvis/.openclaw/mcp-venv/bin/python --arg /var/lib/seven-openjarvis/.openclaw/seven_mcp.py --cwd /var/lib/seven-openjarvis --connect-timeout 30`; execute `openclaw mcp doctor seven-operations --probe`. Se a configuração antiga tiver múltiplos agentes com `default: true`, execute [prepare_seven_mcp.py](prepare_seven_mcp.py) como `sevenjarvis` antes do cadastro, para migrar `agents.ownership` para `explicit` e manter `main` como agente de sistema. O MCP expõe `squad_list`, `squad_status`, `squad_delegate`, `brain_search`, `brain_read` e `brain_save`. A ferramenta de escrita reaproveita a API de perfil com controle de revisão; não recebe caminho de arquivo do modelo.

O processo OpenJarvis ainda mantém o mecanismo Ollama para telas antigas do painel que dependem das rotas genéricas `/v1/*`. Ele não processa mensagens enviadas pela página Seven. A remoção desse mecanismo exige migrar ou aposentar as telas antigas, separadamente, para não quebrá-las.

## Segundo Cérebro decidido pelo Seven

Cada mensagem enviada pela rota `/v1/seven/chat` ainda é acrescentada a `~/.openclaw/seven-memory-inbox/YYYY-MM-DD.jsonl`, com `fsync`, como trilha bruta de recuperação. Isso não dispara decisão ou gravação de nota.

O job antigo `seven-memory-nightly` deve permanecer **desativado**: ele selecionava memórias em lote e gravava Markdown sem o Seven chamar uma ferramenta. O código legado [seven_memory_review.py](seven_memory_review.py) fica apenas para recuperação histórica até sua remoção controlada. Agora o agente de conversa decide quando buscar, ler e salvar pelo MCP. `AGENTS.md` limita o que merece nota e exige confirmar a gravação só depois do retorno da ferramenta. O cofre segue em `~/Documents/Seven Brain`.

Defina `skills.workshop.autonomous.mode` como `propose` no OpenClaw para impedir revisões semanais automáticas de skills, inclusive no perfil do revisor, que poderiam consumir tokens remotos fora do job de memória.

Não recrie o job antigo ao reinstalar o Seven. Não exponha o Gateway, a API local nem o Ollama à internet.
